# Подготовка учебного материала

Работай от корня репозитория Learning Guild. Единственный общий педагогический стандарт — [AUTHORING.md](../../../AUTHORING.md); формат пакета — [LESSON_CONTRACT.md](../../../LESSON_CONTRACT.md). Не поддерживай вторую копию этих правил внутри skill или профиля. Этот skill и стандарт обновляются вместе с приложением через Git; глобальная установка skill и родительская учебная папка не требуются.

## Контекст

Для нового курса сначала прочитай [формат локальных курсов](../../../docs/local-courses.md) и [правила полного roadmap](../../../references/course-creation.md). Материалы и программа лежат в `local-courses/<id>/`, а подтверждённая персонализация — в `local-learning-profiles/<learningProfileId>/` по manifest. Связанный профиль объединяет только пожелания, сведения «Обо мне» и effort; он не переносит темы, результаты или отзывы между курсами.

Прочитай общий стандарт, контракт и `README.md`/`AGENTS.md` выбранного `local-courses/<id>/`, если они существуют; иначе опирайся на manifest и общий контракт. Установи текущую тему, зависимости и доступные инструменты курса. Общий стандарт применим к разным предметам, но Python runner не означает поддержку ML-библиотек: сверяй capabilities курса до обещания запуска.

Личный контекст получай только из выбранного локального профиля или явно предоставленного источника: подтверждённые настройки, актуальные решения и отзывы с известным происхождением. Не ищи профиль по имени ученика и не переноси чужие настройки. Отсутствие профиля не мешает подготовить общий черновик, но персональные выводы в этом случае неизвестны.

Отделяй корректность, объяснение смысла, помощь и нагрузку. Выбери минимальный следующий шаг по таблице стандарта. Для нескольких затруднений одного урока — одна работа над ошибками с разделами; следующая тема остаётся отдельной веткой. Не создавай новый урок, если пользователь просит только изменить один пример.

## Подготовка и доказательство качества

1. Определи учебные цели и формат: урок, короткий разбор или повторение. Каждый новый приём должен получить понятный наблюдаемый пример до самостоятельного применения.
2. Подготовь материал по контракту; данные и контент держи вне визуальных компонентов. Используй стабильные ID опубликованных задач. Не переписывай ученические ответы, прогресс или награды.
3. Для каждой новой или существенно изменённой задачи автор находит простейшее корректное решение без учебных запретов, проверяет необходимость условий и создаёт различающие тесты для 2–3 естественных неверных решений.
4. Передай **отдельному независимому субагенту** ученический текст, цели и тесты без авторских эталонов и авторского заключения. Он проверяет ясность новичку, перенос вместо копирования, обход смысла и получает собственное решение. Сохрани заключение по каждому ID с конкретными входами, различающими правила.
5. Выполни примеры, трассировки, оба решения и неверные варианты настоящим исполнителем курса. Запускай самостоятельную задачу из чистого состояния, без переменных соседнего примера. Условия и отчёт должны соответствовать тому, что действительно проверяют тесты.
6. Проверь пакет через `npm run check:course` (при выборе другого курса уточни аргументы в `local-config.mjs`) и относящиеся к изменению проверки. Для веб-пакета проверь сценарий во временном профиле. Не используй реальные сохранения для QA.

Если независимая или исполняемая проверка не завершена, материал остаётся черновиком с указанной причиной. После смысловой правки повтори проверки затронутых задач. Ревью прежней версии не подтверждает новую.

## Границы сохранения

Общие материалы и обезличенные нормы — в репозитории. Персональные свидетельства, диагностические заметки, отзывы, предпочтения и адаптивные уроки — в локальном профиле. Изменения «Обо мне»/«Как мне давать задания» требуют предусмотренного согласия ученика. Не превращай аудит или отказ от отзыва в автоматическое изменение профиля. Публикация GitHub выполняется по правилам полномочий проекта; skill её сам не разрешает.
