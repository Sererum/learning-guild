# Защищённый запуск учебного Python

По умолчанию приложение требует режим `isolated`. На macOS оно проверяет штатный `sandbox-exec` (Seatbelt) настоящим запуском Python 3.12. Установка пакетов, изменение системной политики или глобальных настроек не нужны. Если средство недоступно или проверка не прошла, код не запускается автоматически в менее защищённом режиме.

## Что ограничено

- Читать содержимое разрешено только из готовой среды Python, доверенных файлов исполнителя, системных библиотек и отдельного временного каталога конкретного запуска. Профили, курс, домашняя папка и прочие каталоги не разрешены. Системные метаданные файлов доступны для работы загрузчика; это не доступ к их содержимому.
- Запись разрешена только во временный каталог запуска и `/dev/null`; каталог удаляется после завершения. Символическая ссылка на внешний файл не обходит ограничение ядра.
- Сеть и создание дочерних процессов запрещены. Дополнительный Python audit hook блокирует обычные API запуска процессов. В тестах отдельно проверяется прямой вызов `fork()` через libc, минуя Python hook.
- Среда запуска очищена от пользовательских переменных окружения; Python использует `-I -S -B` и не загружает пользовательские site-packages. Учебные ограничения AST и доступных функций остаются включены.
- CPU: 3 секунды; запись одного файла: 2 МиБ; открытые дескрипторы: 64; создание процессов: 0. Родитель ограничивает общее время и объём полученного вывода.

## Ограничение памяти

На этой версии macOS `RLIMIT_AS`, `RLIMIT_DATA` и `RLIMIT_RSS` не позволяют выставить пригодный жёсткий лимит. Поэтому используется отдельный наблюдатель резидентной памяти: каждые 20 мс процесс проверяет пик RSS и завершается после превышения 512 МиБ. Это защита от устойчивого расхода, **не жёсткая гарантия максимума**: короткий пик выше 512 МиБ возможен. Интерфейс получает `memoryProtection: "resident-watchdog"` и должен обозначать это честно. На платформах с поддержкой `RLIMIT_AS` bootstrap дополнительно применяет адресный лимит.

## Другие компьютеры и доверенный режим

В текущей реализации системная изоляция подключена только для macOS. Наличие Docker или другого инструмента само по себе не разрешает автоматически запускать демон, устанавливать образы или считать окружение защищённым. На Windows/Linux без подключённого проверенного средства режим `isolated` блокирует исполнение. Подключение контейнера/VM является отдельной настройкой окружения.

Владелец локального приложения может явно выбрать `trusted-local` в настройках после объяснения последствий. Такой режим сохраняет учебные проверки и родительские ограничения времени/вывода, но **не изолирует файлы компьютера и сеть**. На Windows модуль Unix `resource` отсутствует: CPU, RSS и файловые лимиты bootstrap не обещаются и не отображаются как действующие; включены только родительские таймауты/ограничение вывода и учебные проверки. Эта ветка проверена синтетическим отсутствием `resource`, но настоящий Windows-запуск на данном Mac не проверялся. Нельзя обозначать его как защищённый или автоматически включать после ошибки изоляции. Состояние доступности средства и выбранный режим — разные поля.

Песочница уменьшает риск от запуска учебного кода, но не является обещанием защиты от уязвимости ядра или самого Python. Для намеренно вредоносного кода требуется отдельная машина или VM. Codex имеет отдельный механизм ограничений инструментов; режим read-only/no-tools не заменяет изоляцию Python и не даёт оснований объявлять ИИ-процесс полностью изолированным.

## Управление и проверка

Выбранный режим и доступность защиты отображаются раздельно в **Настройки → Данные и безопасность → Запуск Python**. Для перехода в `trusted-local` владелец локального приложения явно подтверждает последствия. Выбирать автора отзыва для настройки не нужно; приложение не предназначено для доступа недоверенных пользователей по сети. Вернуться к `isolated` можно без ослабления полномочий.

Проверочные сценарии находятся в [execution-sandbox.test.mjs](../tests/execution-sandbox.test.mjs): фактический запуск Python и трассировка, запрещённые файлы и сокеты, обход через символическую ссылку, прямой `fork()` через libc, бесконечный цикл и устойчивое превышение памяти. На компьютере без доступного системного исполнителя проверки реальной изоляции явно пропускаются; отсутствие тихого переключения остаётся отдельной проверкой. Поэтому наличие файла тестов не означает, что защита проверена на каждой операционной системе.
