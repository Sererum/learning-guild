# Установка и обновление через публичный GitHub

Общий код и обезличенные материалы передаются через публичный GitHub. Личный профиль и authoring-контекст — только частно. Подтверждённая ссылка предоставляется после фактического создания репозитория; пока её нет, считать публикацию завершённой нельзя. Полная граница — [data-boundary.md](data-boundary.md).

## Первая установка

1. Получить подтверждённый HTTPS-адрес публичного репозитория. Для чтения общедоступного кода чужие токены и доступ к чужому аккаунту не нужны. Права на push настраиваются отдельно.
2. Создать настоящий Git-клон в постоянной папке. Копия app/ из ZIP без .git не получает обновления. Не создавать пустой репозиторий поверх ZIP и не смешивать независимые истории.
3. До первого запуска импортировать переданный владельцем частный профиль. Он содержит progress.json, course-state.json и необходимые личные служебные файлы. Если профиль уже существует, сначала остановить сервер и сохранить резервную копию; стартовый checkpoint не должен затирать дальнейшее обучение.
4. Использовать [profile-transfer.md](profile-transfer.md) для точных команд экспорта и импорта. Если передана папка, сверить её состав и происхождение перед копированием. Не копировать машинные настройки, токены и работающие блокировки.
5. При настройке запуска использовать напечатанный импортом путь: `node tools/deploy.mjs setup --state-file "/полный/путь/импортированного-профиля/progress.json" --port 4327`. ID берётся из profile.json; при явном --profile он обязан совпасть. Не подставлять default вместо исходного ID.
6. Личный каталог course-authoring/ из ZIP хранить рядом с клоном, вне отслеживаемых файлов. Для экспорта notebook явно задать GUILD_AUTHORING_ROOT на папку этого компьютера.
7. Выполнить [ALICE_AGENT_SETUP.md](ALICE_AGENT_SETUP.md) из корня клона: проверить среду, порт, smoke и, после согласия владельца, пользовательский автозапуск. Профиль уже должен быть импортирован.
8. Если работала отдельная копия из ZIP, остановить её и удалить прежний автозапуск перед включением клона. Один профиль — один пишущий процесс.

## Обновление

Остановить сервер, сохранить резервную копию личного профиля и настроек, затем из корня клона:

    git status --short
    git pull --ff-only

При локальных правках, ошибке доступа или расхождении истории разобраться в причине. Автоматические reset --hard, clean, force push и удаление профиля запрещены. После обновления проверить приложение на временном профиле и запустить обычный сервер. Если папка и пути не изменились, пересоздавать пользовательский автозапуск не требуется.

## Два компьютера

Общие правила создания уроков обновляются тем же pull: `AUTHORING.md`, `.agents/skills/course-material/SKILL.md` и промпты приложения находятся внутри репозитория. Агенту достаточно открыть клон и следовать его `AGENTS.md`; копировать глобальные инструкции Codex или родительскую учебную папку для генерации в приложении не требуется. Автор и независимый рецензент получают текущий стандарт; возобновление со старыми входами не сохраняет ревью прежней редакции. Личные интересы, предпочтения и диагностические свидетельства остаются в локальном профиле и не публикуются вместе с правилами. Для отдельного экспорта Colab может по-прежнему понадобиться частный authoring-каталог, как указано выше.

push публикует согласованные изменения общей платформы или обезличенного курса; pull получает их на другом компьютере. Личные решения, отзывы, персональные продолжения, награды и биография не должны попадать в публичные commits. Перенос личного состояния выполняется отдельно частным архивом с согласия владельца. Черновики, просмотренная теория, выбранная задача и позиция страницы зеркалируются в личный browser-state.json. До экспорта нажать «Настройки → Данные и безопасность → Подготовить черновики к переносу», дождаться подтверждения и затем остановить сервер. Подготовленное зеркало входит в частный ZIP и восстанавливается в браузер импортированного профиля. При ошибке или конфликте не закрывать исходную страницу до успешного сохранения.

Автоматического ежедневного push/pull эта инструкция не создаёт. Для начальной публикации используется новое обезличенное дерево с новой историей: прежняя частная .git не передаётся в публичный remote.
