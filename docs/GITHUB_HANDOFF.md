# Установка и обновление через GitHub

GitHub содержит общую платформу, правила, форматы и нейтральные шаблоны. **Любые реальные программы и уроки, даже обезличенные, находятся локально**, вместе с профилями обучения и сохранениями. Граница — [data-boundary.md](data-boundary.md).

## Первая установка

1. Создай настоящий клон подтверждённого владельцем репозитория в постоянной папке. Папка из ZIP без `.git` не получает обновления; не создавай поверх неё пустой репозиторий и не смешивай истории.
2. Прочитай `AGENTS.md`, `README.md`, [правила создания курса](../references/course-creation.md) и [локальный формат](local-courses.md). В публичном клоне нет готового персонального курса.
3. Для нового ученика запусти приложение и создай аккаунт. Для существующего перенеси **всю** папку `local-courses/<id>/` и связанный `local-learning-profiles/<id>/`. При старом формате сначала выполни миграцию курса и полного профиля по [local-courses.md](local-courses.md). Одного прежнего profile ZIP недостаточно для переноса программы.
4. Настрой единый сервер и пользовательский автозапуск по [инструкции установки](ALICE_AGENT_SETUP.md). Настройка развёртывания версии 2 не выбирает отдельный профиль: между курсами переключаются в приложении.
5. Не копируй токены, чужие пути Python/Codex, работающие блокировки и LaunchAgent другого компьютера. Частный каталог экспорта Colab храни отдельно; при необходимости задай его локальный путь через `GUILD_AUTHORING_ROOT`.

## Обновление

Сначала сохрани черновики через «Настройки → Данные и безопасность → Подготовить черновики к переносу», дождись подтверждения и останови сервер. Сделай частную резервную копию локальных курсов, связанных профилей обучения и настроек. Затем из корня клона:

```sh
git status --short
git pull --ff-only
```

При локальных правках или расхождении истории разбери причину. Не применяй автоматические `reset --hard`, `clean`, force push и перезапись личных данных. После обновления выполни проверки на временных данных и запусти сервер. Если менялись папка или формат развёртывания, настрой запуск заново; обычное обновление кода не требует пересоздания исправного LaunchAgent.

Изменения локальных `content.json` и `program.json`, сделанные внешним агентом, загружаются после перезапуска сервера. Правки программы через интерфейс применяются в работающем приложении.

## Что синхронизируется

`pull` получает интерфейс, движок, `AUTHORING.md`, references и общие skills. Установленному агенту достаточно следовать инструкциям клона; личную программу он поддерживает в локальном аккаунте. `push` публикует только согласованные общие изменения после проверки списка файлов и отдельного разрешения на публикацию. Личный прогресс не отправляется в GitHub ни ежедневно, ни при обновлении приложения.

Общий профиль обучения связывает лишь «Обо мне», подтверждённые пожелания подачи, effort и напоминания. У связанных курсов независимы программы, уроки, решения, отзывы, ресурсы и история. Перед изменением общих настроек интерфейс запрашивает согласие для перечисленных курсов.

Эта инструкция не создаёт расписаний и не включает автоматический push. Если владелец просит периодический pull, согласуй время и поведение при занятии, сохрани черновики, обновляй только чистое дерево без расхождения веток и сообщай о блокере. Обновление не должно прерывать активную работу без согласованного окна. Старые версии приложения и частные архивы сохраняются локально для возврата; историю удалённого репозитория миграция не переписывает.
