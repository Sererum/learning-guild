# Публичный код и локальные данные

Публичный GitHub предназначен для платформы и обезличенных учебных материалов. Успех публикации подтверждается отдельно фактически доступным удалённым репозиторием; наличие локального Git и ZIP не означает, что он уже создан.

| Содержимое | Где хранится | Через публичный GitHub |
| --- | --- | --- |
| Общий интерфейс, игровой движок, исполнитель, API | public/, shared/, server.mjs и общие модули | Да, после проверки |
| Обезличенные уроки, примеры, задания, общая карта и награды | courses/<id>/ | Да; без биографии, подтверждённого прохождения и частного checkpoint |
| Синтетические тесты и авторские эталоны | tests/ | Да; публичный исходник означает доступность этих эталонов любому читателю |
| Общие правила объяснений и техническая документация | AUTHORING.md, LESSON_CONTRACT.md, docs/ | Да; без цитат ученика, реальных балансов и личных отчётов |
| Подтверждённые темы, текущий урок, персональные статусы и ограничения | profiles/<course>/<profile>/course-state.json | Нет; частный ZIP профиля |
| Прогресс, предметы, награды, проверки решений, отзывы, согласия и бюджет ИИ | вся папка profiles/<course>/<profile>/ | Нет; частный ZIP профиля |
| Личные пожелания, интересы и биографический контекст | personalization*.json рядом с прогрессом | Нет |
| Сгенерированные по личному фидбеку уроки и авторские проверки | adaptive/ внутри профиля | Нет автоматически; для общего курса нужна отдельная обезличенная авторская версия |
| Серверные проверки, запросы и ответы ИИ, версии условий | checks/, reviews/ и другие служебные файлы профиля | Нет |
| Черновики кода, просмотренная теория, выбранная задача и позиция чтения | localStorage выбранного профиля и его локальное зеркало browser-state.json | Нет; после подтверждённой подготовки зеркало входит в частный ZIP |
| Машинные пути, порт и настройка запуска | local.config.json, local-data/deployment*.json, LaunchAgent | Нет; создаются заново на целевой машине |
| Блокировки работающего профиля | .guild-lock.json и временные lock-файлы | Не переносятся ни в Git, ни как готовая блокировка другого компьютера |
| Учебный журнал, биография, личный roadmap, сданные работы и персональные notebooks | частная course-authoring/ и python_exports/ владельца | Нет; отдельно от публичного клона |
| Частные копии прежних служебных отчётов | local-data/publication-private-docs/ | Нет |
| Токены, ключи, авторизация Codex и GitHub | штатные хранилища владельца | Никогда не копируются в Git или передаваемый ZIP |
| Личные фотографии и узнаваемые производные иллюстрации | assets/ внутри выбранного профиля | Нет; переносятся только частным профилем. Общий публичный интерфейс использует нейтральный символ |

.gitignore защищает от обычного добавления новых локальных файлов, но не удаляет уже отслеживаемый файл и не стирает его прежние версии. Проверяются текущее дерево, индекс и вся история, которая уйдёт в remote.

## Личные изображения

Обработчик `/assets/<имя>.png` сначала проверяет папку `assets/` только выбранного сервером профиля. Разрешены обычные PNG с безопасным именем, без символьных и жёстких ссылок, до 8 MiB, не более 4096 пикселей по стороне и 16 миллионов пикселей суммарно. Проверяются сигнатура и заголовок изображения; это не универсальный антивирусный анализ файлов.

API добавляет вычисленную `state.profileAssets` только при наличии разрешённых изображений. В ней только относительные URL: абсолютные пути и содержимое файлов не передаются. Поле не сохраняется в прогресс и не берётся на доверии из импортированного JSON. Ответы личных изображений имеют `Cache-Control: no-store` и `Cross-Origin-Resource-Policy: same-origin`.

Без личных иллюстраций персонаж отображается нейтральным созвездием и общим значком. Явно выбранный портрет учитывается только при наличии разрешённого изображения в этом профиле. Прежние персональные имена файлов никогда не используют запасной поиск в `public/assets/`; обычные общие иллюстрации предметов продолжают загружаться оттуда. Смена профиля не предоставляет доступ к изображениям другого профиля.

## Черновики и положение в уроке

Код, в том числе ещё не проверенный на тестах, просмотренная теория, выбранная задача и положение страницы автоматически зеркалируются из браузерного хранилища в `browser-state.json` рядом с прогрессом. Это личный файл выбранного профиля: его переносит полный ZIP, а публичный GitHub не получает.

Перед экспортом открыть «Настройки → Данные и безопасность», нажать «Подготовить черновики к переносу» и дождаться подтверждения. Только после этого остановить сервер и создать архив. При ошибке сохранения или конфликте вкладок не закрывать страницу: текущий код остаётся в браузере, причину нужно устранить и повторить подготовку. На новом компьютере зеркало восстанавливается в браузер того же курса/профиля; отличающиеся прежние локальные значения сохраняются в архивной записи. Зеркало не является зачётом задачи и не выдаёт награды.

## Частный checkpoint и обновление

Публичный клон содержит каталог, а не личный учебный маршрут. Для продолжения обучения нужен полученный от владельца профиль: course-state.json с подтверждённой историей и представлением пути вместе с progress.json и остальными личными файлами. Не восстанавливать персональные статусы из подписи общедоступного урока и не вносить их обратно в rules.json или presentation.json.

При переносе используйте отдельный архив профиля, сохраняющий проверки, отзывы, персонализацию, adaptive-материалы, согласия, бюджет, версии и подготовленное зеркало черновиков. Чужие блокировки и машинный режим исполнения не переносятся: целевая среда проверяется и использует isolated. Возможности, точные команды и ограничения инструмента — [profile-transfer.md](profile-transfer.md). До импорта сервер остановлен, назначения не существует либо владелец явно согласовал восстановление после резервной копии. Не распаковывать стартовый ZIP поверх дальнейшего прогресса. ZIP не шифрует личные данные: его передают доверенному получателю частным каналом, а не прикладывают к публичному issue или GitHub release.

pull обновляет код и общие материалы, а не личный профиль. После обновления сохранение остаётся на месте. Для передачи между компьютерами согласуется отдельный частный перенос; публичный push не является резервной копией ученика. Автоматические ежедневные push/pull здесь не включаются.

## Безопасная начальная публикация

Прежний локальный репозиторий содержит частные исторические записи; очистка файлов только в HEAD недостаточна. Для первой публичной публикации нужен отдельный проверенный снимок текущего обезличенного дерева и новая начальная Git-история. Исходную частную историю не переписывать и не копировать её .git, ветки, теги или bundles в публичный репозиторий. Не применять push --mirror, --all или --tags к прежнему репозиторию.

До отправки отдельно сверяют точный состав, синтетичность тестов, assets и метаданные автора коммита. Публикация и каждый последующий push выполняются по действующим правилам согласования внешних действий. Подтверждённая ссылка и ветка указываются только после успешного создания и проверки удалённого репозитория.
