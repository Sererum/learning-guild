Названия переменных, типы результата и вывод обозначены в условиях. Для трёхзадачных разборов сложность растёт от одного действия к переносу; отдельные разборы 2.3 тренируют конкретные операции словарей и множеств. ## Найденные и закрытые дыры

1. `repair-clean-3`: `text = "Пришёл доставщик"` → `clean_text = "пришёл доставщик"`, `needs_delivery = False`. В строке нет ни «доставка», ни «доставку», хотя общий префикс есть.
2. `repair-index-2`: `message = "::чай::кофе"`, `marker = "::"` → `marker_index = 0`, `suffix = "чай::кофе"`. Первый и последний маркер дают разные ответы.
3. `repair-index-3`: `email = "a@b@c"` → `at_index = 1`, `domain = "b@c"`. Учебное условие требует первый @ и не вводит исключение для таких строк.

Автор добавил все три контраста в настоящие `task.tests` и пересобрал notebooks 1.4b и 1.4c. Независимый повторный прогон тем же runner подтвердил: прежние три ложноположительных решения теперь отклоняются именно по результату, все эталоны продолжают проходить. Блокеров в проверенном комплекте не осталось.

## Корректные альтернативы

Отдельно проверено: `name[-1:]` проходит все настоящие тесты `repair-index-1` с действующими ограничениями. Для `repair-while-1` формула `max(progress, goal)`, для `repair-while-2` целочисленное округление числа пополнений вверх проходят реальные наборы при снятом только учебном требовании while; их не следует описывать как неправильные алгоритмы. Само требование while обозначено в тексте и в проверке как тренировка ручного способа.
