# Ежедневное повторение

У каждого локального курса свой дэйлик: одно короткое проверенное задание на календарный день. Программа и подтверждённое освоение темы определяют доступность; наличие материала или его просмотр не считаются освоением.

## Банк заданий

Курс предоставляет `course.daily` (локальное хранилище может загрузить его из `daily.json`):

```json
{
  "timeZone": "Europe/Moscow",
  "reward": {"gems": 60, "gold": 100, "books": 1, "materials": {"ore": 2}},
  "variants": [
    {
      "id": "topic-repeat-a",
      "topicId": "program-node-id",
      "title": "Короткое название",
      "prompt": "Самостоятельное условие с ожидаемыми переменными и выводом.",
      "starter": "# Напиши решение здесь",
      "reviewed": false,
      "tests": [{"label": "Название сценария", "inputs": {}, "expected": {"answer": 1}}]
    }
  ]
}
```

Это пример структуры, не готовый учебный материал. Каждый вариант проходит общий стандарт `AUTHORING.md`, независимую проверку ясности и обходов, запуск корректного решения и различающих неверных решений. Только после этого автор ставит `reviewed: true`; черновики никогда не выдаются. Тесты используют обычный исполнитель курса, поддерживаются `constraints` и скрытые сценарии. Примерные значения наград в банке можно изменять для будущих выдач. Текущая выданная задача, тесты и награда зафиксированы до конца её дня.

Нужны разные условия и входные данные, а не переименование одной задачи. Запас нескольких вариантов по каждой освоенной теме готовится заранее. Общая платформа не содержит персональные банки: они остаются рядом с локальным курсом. Если подходящего проверенного задания нет, интерфейс сообщает об этом и не обещает недоступную награду.

## Ротация

1. Доступны только варианты по `program.nodes`, где `completed: true` и нет `excluded`.
2. Когда доступно несколько тем, исключается тема последнего выданного дэйлика. Из остальных выбирается тема с наименьшим количеством выдач.
3. При равенстве счётчиков выбор псевдослучаен и воспроизводим из ID курса/профиля, даты и ID темы. Внутри темы таким же образом чередуются варианты.
4. Пропущенная задача считается выданной: пропуск не позволяет постоянно получать одну тему. Пропущенные календарные дни не создают очередь долгов.
5. Новая тема допускается только после освоения. Изменение программы не подменяет уже выданное задание посреди дня.

Для неизменного набора тем ротация распределяет выдачи равномерно и избегает соседних повторов. Когда освоена только одна тема, повторяется тема, но варианты чередуются. При изменении набора тем преимущество получают менее часто выданные темы, с сохранением запрета соседнего повтора при наличии альтернатив.

## Проверка, награда и полночь

Сервер определяет дату в часовом поясе банка, затем manifest курса; по умолчанию используется `Europe/Moscow`. Следующая граница вычисляется как реальная местная полночь, включая переходы на летнее/зимнее время. Обновление страницы и перезапуск сервера не меняют задание.

Проверка сохраняет код и результат, но не начисляет валюту. После успешного прохождения всех тестов появляется действие «Забрать награду». Нажать его нужно до полуночи. Начисление ресурсов и отметка получения сохраняются одной записью состояния; повторное нажатие ничего не выдаёт. Не полученная награда сгорает, уже полученные ресурсы не отнимаются.

Любая проверка и получение награды сверяют ID, дату и срок на сервере. После завершения долгой проверки срок проверяется повторно: вчерашняя вкладка не может зачесть решение новому дню или получить старую награду. Перевод часов назад не возвращает уже сменившийся дэйлик.

Полная история назначений, последние 30 проверок каждого задания и его последнее успешное решение хранятся локально в `progress.daily.entries`. Публичный ответ содержит только безопасное представление `daily`; приватный `state.daily` с исходными тестами не должен возвращаться браузеру. История не даёт повторных наград, не засчитывает основные уроки и не меняет учебный маршрут.

## Интеграция

`createDailyService({readCourse, readProgram, readState, persist, clock, scope})` использует существующую блокировку профиля и единственный атомарный writer сохранения. Методы: `snapshot()`, `task(id)` для исполнителя, `recordCheck(id, {code, result})`, `claim(id)`. `clock` внедряется только сервером/тестами, никогда клиентом. HTTP-обработчик обязан применять общие проверки источника запроса и сессионного токена, ограничение длины кода, обычную изоляцию Python и отклонение старого ID после выполнения.
