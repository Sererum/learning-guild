# Проверка переносимого комплекта

Проверяют скопированное приложение из комплекта. Личный checkpoint, балансы и учебная история фиксируются в локальном отчёте владельца, а не в публичном репозитории.

1. Сверить контрольные суммы и наличие приложения, инструкции агенту и частной авторской папки, если владелец её передал.
2. Выполнить doctor и smoke из копии приложения. Для HTTP использовать временный порт и отдельную копию профиля; исходный профиль должен остаться байт-в-байт прежним.
3. Проверить стартовый checkpoint по частному описанию владельца. Нельзя угадывать пройденные темы и текущий урок по публичному каталогу.
4. Проверить карту, книгу, выбранный урок, разборы и дэйлик в отдельном профиле. До частного ZIP нажать «Подготовить черновики к переносу», дождаться подтверждения и проверить восстановление browser-state.json с непроверенным кодом, просмотренной теорией и позицией чтения. Повторная выплата, смена дня и состояние тумана проверяются автоматическими сценариями.
5. Выполнить tests/execution-sandbox.test.mjs и tests/deploy.test.mjs. Успешный capabilities probe подтверждает доступность запуска, а не защиту от всех возможных обходов.
6. Проверить ссылки authoring-skills. Исторический указатель не означает наличие сданной работы: отсутствующие экспорты нельзя заменять фиктивными файлами.
7. После последней правки PDF, инструкций и частного профиля сформировать SHA-256 и ZIP заново.

Проверки автозапуска ограничиваются планом и синтаксисом до согласия владельца на LaunchAgent. Реальный вход пользователя, сеть и доступность модели проверяются на целевой машине. Не включать небезопасный fallback при недоступной защите.
