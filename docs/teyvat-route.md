# Размещение программы на атласе

`buildTeyvatRoute(data, atlasRegions, {pass: 0})` из `public/teyvat-route.js` — чистое отображение серверного `data.program`. Оно не читает хранилище, не меняет входные данные, зависимости, доступность, награды или результаты.

`atlasRegions` содержит ровно восемь регионов в географическом порядке путешествия: `{id, name, portals: [{x, y}, …]}`. В каждом регионе ровно 12 фиксированных порталов; координаты — проценты ширины и высоты изображения. Сама география хранится отдельно от курса.

Порядок путешествия: **Мондштадт → Ли Юэ → Инадзума → Сумеру → Фонтейн → Натлан → Нод-Край → Снежная**. Сначала Мондштадт и Ли Юэ, затем Инадзума — в привычной последовательности регионов. Это географическое оформление: состав, порядок и зависимости учебных блоков не меняются. На каждом следующем проходе порядок регионов повторяется.

- `passesCount`, `pass`, `passes`: число проходов, выбранный индекс (с нуля) и полный список `{index, label, blockIds, nodeIds}`. После восьмого блока начинается новый проход с Мондштадта. Индекс блока определяет проход `floor(index / 8)` и регион `index % 8`; исключение уроков не сдвигает блоки. Индекс выбора ограничивается существующими проходами.
- `regions`: география и соответствующий блок текущего прохода (`blockId`, `blockTitle`, `pointIds`). Блоки закрепляются за регионами в порядке `program.blocks`.
- `slots`: всегда 96 мест со стабильными ID `<region>:portal:01`…`12`; `nodeId: null` означает свободное место. Свободное место не является уроком.
- `points`: клоны исходных узлов, дополненные `nodeId`, `region`, `slotId`, координатами и `current`. Полный маршрут включает будущие узлы с исходным `status: 'future'`; отображение должно окрашивать их серым.
- `routes`: визуальная последовательность уроков, затем боковые ветки разборов. Это **не зависимости обучения**. `skippedNodeIds` перечисляет уроки между концами линии, помещённые в список продолжения из-за вместимости.
- `overflow`: видимые узлы текущего прохода, которым не назначено место на карте. Интерфейс обязан показать их в списке продолжения с исходными действиями: `region-capacity` — больше 12 уроков в блоке, `side-branch` — дополнительная ветка, `unassigned` — блок не найден (показывается на первом проходе). Девятый и следующие блоки получают места следующего прохода, а не попадают в переполнение.

`points`, `routes`, `slots` и `overflow` относятся только к выбранному проходу. Все исходные ID узлов сохраняются между переключениями. ID физических порталов повторяются, поскольку это те же места карты; они не заменяют ID уроков. Ветки следуют проходу родительского урока. Переключатель интерфейса хранит выбранный проход отдельно от выбранного ID урока.

Порядок уроков внутри блока берётся из `program.nodes`. Исключённые уроки не выводятся, но сохраняют пустое место, чтобы остальные порталы не смещались. В коротком блоке маршрут переходит к первому занятому месту следующего региона, пропуская свободные порталы.

Все работы над ошибками одного размещённого урока объединены в одну точку `atlas-repair:<parentId>` с `members` и `sourceNodeIds`. Исходные ID, материалы и доступность каждой работы сохранены в `members`; открывать следует выбранный доступный материал, а не синтетический ID точки. Прочие дополнительные ветки и разборы уроков из списка продолжения остаются в `overflow`.

Пример: `const atlas = buildTeyvatRoute(data, ATLAS_REGIONS, {pass: 1});` — отрисовать второй проход, 96 `slots`, поверх занятых мест поставить `points`, рядом обязательно показать `overflow` и переключатель `passes`. Для правил открытия использовать исходные поля серверного узла и его материалов.

При подготовке новой программы агент по возможности объединяет близкие темы в содержательные крупные блоки, чтобы один блок соответствовал одному региону и содержал не больше 12 основных уроков. Объединение должно сохранять учебную логику, цели и зависимости; нельзя незаметно переписывать уже согласованную личную программу ради карты. Если логически уложиться в восемь блоков нельзя, используется повторный проход по тем же регионам. Свободные порталы короткого блока пропускаются: искусственно добавлять уроки для заполнения карты не нужно.

## Значки, статуи и туман

Общий набор `public/map-icons.js` сохраняет контуры согласованного макета: белая рамка телепорта, голубая вставка, круглая статуя, синий знак разбора и фиолетовое ежедневное поручение. Неактивные статуя и телепорт имеют ту же форму с серой вставкой. Если у урока есть доступный незавершённый разбор, его телепорт становится золотым; после выполнения разбора обычный цвет восстанавливается. Это подсказка, а не изменение зачёта или доступа.

`worldItinerary()` проводит маршрут через обязательные уроки, затем статую своего блока, затем первый урок следующего региона. Итоговый экзамен (последний обязательный узел с `kind: "exam"`) отображается статуей и не дублируется телепортом. Он закрыт до подтверждённого прохождения остальных обязательных уроков; на сервере проверяется тот же доступ. Завершённые материалы можно повторно открывать. Необязательные диагностические экзамены по запросу «я уже знаю» остаются отдельными ветками и подтверждают только свои цели.

Если программа не содержит итогового экзамена блока, статуя показывает завершение обязательных уроков и не обещает отсутствующий тест. Добавление учебного материала выполняется через обычное согласование программы и независимое ревью, а не рисованием значка.

`fogReveals()` выбирает готовые территории по пройденным урокам. При нулевом прогрессе география полностью скрыта непрозрачным тёмным слоем. Никакая стартовая площадка заранее не открывается. Все границы заранее записаны плавными векторными кривыми: [контракт и привязка территорий](../references/map-territories/README.md). После завершения всего обязательного блока открывается остаток региона. Просмотр, доступность, выбор точки и создание материала не раскрывают туман.
