# Для локального агента установки

Разверни приложение из подтверждённого публичного клона либо из локального комплекта. Код и общие материалы не содержат персонального checkpoint. Личный профиль передаётся владельцем отдельно и импортируется до первого обычного запуска; порядок — [GITHUB_HANDOFF.md](GITHUB_HANDOFF.md). Не подменяй дальнейшее обучение стартовым сохранением.

## До начала

- Уточни ОС. **Защищённый исполнитель этой сборки поддерживает только macOS с работающим Seatbelt.** На Windows/Linux остановись и сообщи об отсутствии подключённой изоляции. Не включай `trusted-local`, не обходи политики ОС и не выдавай запуск без защиты за готовую установку.
- Нужны уже установленные Node.js **20+**, Python **3.12**, Codex CLI с входом в личный аккаунт владельца. npm-зависимостей нет: `npm install` не нужен.
- Установку недостающих программ, загрузки из сети, вход в аккаунт и любые изменения прав предварительно согласуй с владельцем. Если вход уже есть, не выполняй повторную авторизацию. Не читай и не копируй хранилища токенов.
- Автозапуск после входа входит в запрошенную установку; повторное разрешение на согласованный шаг не требуется. Покажи в отчёте: один LaunchAgent `local.learning-guild.<ID профиля>`, порт, папку приложения и логи. Не используй `sudo`, системные службы или доступ из локальной сети.

## 1. Распаковка и проверка

Выбери постоянную папку пользователя. Для обновлений создай настоящий клон подтверждённого публичного репозитория; отдельно полученный ZIP профиля не заменяет Git-клон. Если используется локальный комплект `AliceLearning`, приложение находится в подпапке **`app/`**, а частный authoring-контекст — рядом в **`course-authoring/`**. Не запускай из ZIP, временной папки или сетевого диска. Корень приложения определяется по `package.json`, `server.mjs`, `tools/`, `courses/`; личный `profiles/` переносится отдельно.

Все команды ниже выполняй из **корня клона** либо из **`AliceLearning/app/`** при локальной установке. На macOS перед Python загрузи пользовательские настройки оболочки без вывода (`source ~/.zshrc >/dev/null 2>&1`), если файл существует. Не выводи всё окружение.

```sh
node --version
node tools/deploy.mjs doctor
```

Если Python или Codex не найден, укажи полные пути **этого компьютера**:

```sh
node tools/deploy.mjs doctor --python "/полный/путь/python3.12" --codex "/полный/путь/codex"
```

Проверка выполняет штатный `codex login status`, не печатает данные аккаунта и не делает запрос к модели. Она подтверждает версию Python и успешный запуск с политикой Seatbelt. Это проверка доступности исполнителя, **а не доказательство защиты от всех возможных обходов**. Отдельно выполни включённые негативные проверки:

```sh
node --test tests/execution-sandbox.test.mjs
```

На поддерживаемом Mac проверки изоляции должны пройти без пропусков: тестовые внешние файлы, сокет, дочерний процесс, симлинк и ограничения ресурсов. Они используют синтетические данные и временные каталоги; исчерпывающим аудитом безопасности они также не являются. При ошибке устрани причину или сообщи о блокере; не отключай защиту.

## 2. Локальная настройка и проверочный запуск

```sh
node tools/deploy.mjs setup --state-file "/полный/путь/импортированного-профиля/progress.json" --port 4327
node tools/deploy.mjs smoke
node tools/deploy.mjs start
```

Используй точный путь, напечатанный импортом. `setup` читает исходный ID из `profile.json`; `course-state.json` должен принадлежать тем же курсу и профилю. Можно явно указать `--profile ID`, но несовпадение запрещено. Например, импортированный `alice-mvp` нельзя незаметно заменить на `default`. Неполный перенос одного `progress.json`, чужой курс, ссылка вместо файла и несуществующий явно указанный путь останавливают настройку без изменения профиля. Для отдельного нового профиля допустим `setup --profile ID` без `--state-file`; это не способ восстановления личного checkpoint.

В `setup` добавь те же `--python` и `--codex`, если они понадобились в `doctor`. Если порт занят, выбери другой свободный порт (например `4337`) через `--port`; чужой процесс не останавливай. Адрес всегда `127.0.0.1`, доступ извне не открывай.

`setup` один раз сохраняет пути этого компьютера в `local-data/deployment.json`. Он не перезаписывает существующую настройку. `smoke` проверяет защищённый Python, тесты и HTTP на **временном профиле и порту**, не трогая прогресс владельца.

Открой напечатанный адрес `http://127.0.0.1:4327/#world`. Проверь карту, уроки и значения частного checkpoint по описанию владельца; не угадывай персональные статусы из публичного каталога. Код и тесты нажимай в отдельном проверочном профиле, чтобы не начислить владельцу тестовые награды. В основном профиле проверь только отображение; стартовые данные не заменяй новым пустым профилем.

Для проверки живого ответа Codex предупреди об одном платном/лимитируемом запросе и согласуй его. `doctor` подтверждает вход, **но не обещает успешный ответ модели**: его доступность, квоты и сеть проверяются отдельно. Убедись на временном профиле, что подсказка не выдаёт полное решение, ревью работает после тестов, ошибка подключения видна и не начисляет бонус.

## 3. Автозапуск после входа в macOS

Сначала останови ручной запуск — в другом окне терминала из той же папки:

```sh
node tools/deploy.mjs stop
node tools/deploy.mjs autostart --dry-run
```

Посмотри план. После ранее согласованного разрешения включи:

```sh
node tools/deploy.mjs autostart
node tools/deploy.mjs status
```

Создаётся только `~/Library/LaunchAgents/local.learning-guild.<ID профиля>.plist`. Служба стартует в текущем пользовательском сеансе и при следующем входе; выключенный компьютер она не включает. Проверь адрес и журнал после реального повторного входа при возможности. Бесконечных автоматических перезапусков нет: при ошибке смотри логи.

## Управление

| Нужно | Команда / место |
| --- | --- |
| Проверить адрес | `node tools/deploy.mjs status` |
| Запустить вручную | `node tools/deploy.mjs start` (окно терминала оставить открытым) |
| Остановить сейчас | `node tools/deploy.mjs stop` |
| Убрать автозапуск | `node tools/deploy.mjs uninstall-autostart` |
| Журналы автозапуска | `local-data/logs/server.log`, `local-data/logs/error.log` |
| Личный прогресс, отзывы, ИИ и персонализация | папка stateFile из `local-data/deployment.json`; обычно `profiles/alice-python/<ID>/` |
| Пути и порт этого компьютера | `local-data/deployment.json` |
| Уроки и карта | `courses/alice-python/` |

Остановка выгружает LaunchAgent из текущего сеанса; файл остаётся для следующего входа. Удаление автозапуска не удаляет приложение и личные данные. Повторное включение после `stop`: сначала `uninstall-autostart`, затем `autostart`.

Перед экспортом личного ZIP открой «Настройки → Данные и безопасность», нажми «Подготовить черновики к переносу» и дождись подтверждения. Это сохраняет непроверенный код, просмотренную теорию, выбранную задачу и позицию чтения в `browser-state.json`. При ошибке или конфликте вкладок исходную страницу не закрывай до успешного сохранения. После подтверждения останови сервер, выполни экспорт и перенеси полный профиль по [profile-transfer.md](profile-transfer.md).

Один профиль — один процесс. Не запускай одновременно `npm start` и `deploy.mjs start`; не снимай блокировку у работающего сервера. Для обновления останови приложение, сделай резервную копию `profiles/` и `local-data/`, обнови только код/курс и запусти снова. Не переноси чужие `local.config.json`, `deployment.json`, LaunchAgent, токены или `.guild-lock.json`. При переносе папки заново создай настройку и автозапуск с новыми полными путями.

После установки сообщи владельцу только адрес, как открыть урок и где лежит короткий гайд. Технические детали оставь в локальном отчёте без секретов.

Публичная граница данных — [data-boundary.md](data-boundary.md). Личный `course-state.json`, персонализация, отзывы и adaptive-материалы входят в частный профиль, а не в GitHub. Копия стартового профиля не накладывается поверх дальнейшего прогресса.
