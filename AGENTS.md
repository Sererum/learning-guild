# Learning Guild: правила разработки

Этот каталог — репозиторий общей платформы и проверенных учебных материалов. Личные профили, журнал обучения, ответы, отзывы и авторские контексты хранятся отдельно. Границы публикации — [docs/data-boundary.md](docs/data-boundary.md). Не переносить личные работы или их пересказ в исходники, тесты, документацию и историю Git.

## Границы

- `shared/`, `server.mjs`, `runner.py`, `public/` — общая платформа. Здесь не должно появляться ветвлений по ID уроков или ученику.
- `courses/<id>/` — общие уроки, карта, зависимости, учебные награды и оформление курса. Подтверждённое прохождение, жёлтые темы и персональные ограничения доступности принадлежат локальному профилю. Карта/книга читают общий `public/journey.js` и одинаково трактуют зависимости и состояние.
- `profiles/`, `data/`, `local-data/`, `imports/`, `qa-data/`, `local.config.json` — личные данные и настройки, исключены из Git. Не сбрасывать и не подменять реальные результаты.
- Корневые адаптеры старых учебных модулей нужны для совместимости импортов. Не создавать вторую редактируемую копию содержания.

## Разработка и проверка

Адрес и порт выбираются на компьютере владельца; сервер слушает только loopback. Не запускать два процесса для одного профиля и не оживлять архивные демонстрационные серверы. Перед параллельными правками согласовать владение файлами.

Все проверки используют временные stateFile и временные порты, после проверки серверы закрываются. Не направлять автотесты на рабочий профиль. Проверять сохранность состояния при миграциях; изменения данных не должны повторно начислять награды. Нельзя одновременно писать один профиль из нескольких процессов.

Рабочий Python — готовая версия3.12, выбирается `local-config.mjs`; не создавать venv и не устанавливать зависимости без отдельного разрешения. `npm test` выбирает runtime и запускает переносимые проверки. Браузерные проверки используют уже установленный Playwright/Chrome.

При новом курсе обязательно проверить его на том же общем интерфейсе с другими ID, картой и наградами; проверить, что его серверные и браузерные сохранения не смешиваются с существующими. Изменения схемы должны сохранять стабильные ID старых задач и неизвестные поля прогресса.

При создании или исправлении оружия, артефактов, украшений, нарядов и графики новых баннеров применяй [.agents/skills/equipment-art/SKILL.md](.agents/skills/equipment-art/SKILL.md) и [контракт экипировки](docs/equipment-art-contract.md). Предметы адаптируются к канонической позе и креплениям персонажа через общий manifest; парящая иконка не заменяет надетый слой.

## Учебный контракт

Общий стандарт — [AUTHORING.md](AUTHORING.md), данные/API — [LESSON_CONTRACT.md](LESSON_CONTRACT.md). Для каждого курса дополнительно читать его README и AGENTS.md. Профиль ученика и фактический фидбек предоставляются отдельным контекстом. Учебный контент нельзя зашивать в визуальные компоненты.

Для создания и существенной правки урока, работы над ошибками или дэйлика применяй [.agents/skills/course-material/SKILL.md](.agents/skills/course-material/SKILL.md). Это переносимый вход в общий стандарт; он не зависит от родительских папок и личных файлов автора. Изменение стандарта должно учитываться и автором, и независимым рецензентом; старые checkpoints с другими входами не подтверждают новый материал.

Каждую новую или существенно изменённую задачу проверяют автор и независимый субагент: ясность новичку, простейшее корректное решение, возможность обойти учебную цель, естественные ошибочные варианты на настоящих тестах. Готовые решения допускаются только в разобранных примерах и закрытых проверочных материалах.

ИИ даёт подсказки без готового решения; ревью после успешных тестов оценивает три качества отдельно. Medium по умолчанию, вопрос открывается по кнопке, Enter отправляет. Выплаты рассчитывает сервер, просмотр не активирует телепорт. Просмотренная теория и выполненные задачи зелёные, проверенные задачи с ошибками жёлтые.

Отзыв после пропуска можно добавить, заполненный — исправить явной кнопкой; автоматическая форма повторно не навязывается. Предыдущие редакции сохраняются локально. После явной отправки урока адаптация сначала обновляет `personalization.json` выбранного профиля, затем готовит продолжение по `course.adaptation`. Нельзя запускать такую обработку на реальном профиле ради QA. Материалы в `adaptive/` подключаются только после проверок и независимого ревью; генерация не даёт зачёт и валюту. Общие предложения не применяются автоматически к файлам правил, коду или чужим профилям.

Меры управления рисками описаны в `docs/risk-controls-acceptance.md`. Персональные разделы — «Обо мне» и «Как мне давать задания»; новые отзывы оставляет только ученик, старое авторство не переписывается. Любое предложенное ИИ изменение профиля требует явного согласия; отказ от всех изменений разрешает продолжить подготовку с текущими настройками. Не подменять согласие повторением отзывов или восстановлением после перезапуска. Изменение условия требует новой проверки текущей версии, но не повторной выплаты; старые решения архивируются. Все обращения к модели учитывают общий бюджет профиля. Python по умолчанию требует проверенного системного исполнителя; ошибка защиты не разрешает тихое переключение в доверенный режим. Общее правило применяется локально только после отдельного ревью и явного подтверждения точного текста и области действия. При параллельных профилях сохранять блокировку и контроль редакции общего хранилища.

Публикация репозитория, push и другие внешние действия выполняются только после отдельного согласования. Наличие локального Git-репозитория само по себе не разрешает отправку данных на GitHub.
