# Локальное продолжение обучения

`createLearningService` запускается сервером для одного курса и одного локального профиля. Работа начинается только после явной отправки урока. Проверка задачи, просмотр урока, получение награды, обновление страницы и опрос статуса не запускают генерацию.

## Порядок

1. Сохраняется неизменяемый снимок подтверждённых проверок, проверенного кода и отзывов. Код учитывается только при совпадении SHA-256 с сохранённой проверкой. Старый результат без кода остаётся ограниченным свидетельством; отсутствие результата не считается ошибкой.
2. В `personalization.json` записываются прямые наблюдения. Отдельный запуск Codex выделяет педагогические предпочтения, каждое со ссылкой на содержательный отзыв. Эти правила применяются **до** подготовки нового материала. Личность автора веб-прохождения не угадывается по названию курса.
3. Проверяемые факты и самооценка определяют ветку. Локальное затруднение даёт короткую работу над ошибками; затруднения в нескольких задачах — закрепляющий урок. Следующая тема roadmap готовится отдельно. Подсказка или низкая оценка одного ревью сами по себе не являются провалом, а зелёные тесты не объявляются полным освоением.
4. Автор создаёт только JSON. Следующая тема берётся из программы курса, награды — из его явной конфигурации. Новый урок и повторение не смешиваются. Для неподключённого исполнителя, например будущего SQL/Pandas, материал не активируется и зависимости не устанавливаются.
5. Ограниченный Python-исполнитель проверяет примеры, их точный вывод, каждое ручное состояние, заготовки без решений, эталоны и минимум два естественных ошибочных решения на настоящих тестах.
6. Второй независимый контекст Codex получает материал без эталона автора и сам решает каждую задачу. Его решения и ошибочные варианты тоже исполняются. Вызовы используют отдельные временные директории и `--ephemeral`; shell, приложения, плагины, MCP и веб-поиск отключаются для процесса, глобальные настройки не меняются. Это независимые контексты одной модели, а не гарантия отсутствия общих ошибок.
7. После независимого ревью и проверки полного объединённого пакета атомарно появляется локальная публикация. При сбое прежние уроки и результаты не меняются; уже применённые предпочтения сохраняются.

## Файлы профиля

```text
personalization.json
adaptive/
  jobs/<id>.json
  jobs/<id>/attempt-<n>/<stage>/...
  published/<id>.json
```

В заданиях хранятся частные доказательства, код, ответы автора и рецензента. В опубликованных серверных задачах остаются проверочные случаи; эталоны туда не попадают. В публичном статусе адаптации — только стадия, диагностический итог, версия предпочтений и ссылки на ветки. Этот статус не содержит исходных отзывов, промптов и закрытых проверочных материалов. Собственные отзывы ученика доступны его обычному интерфейсу редактирования. Папка профиля находится вне Git.

Текущий генератор использует JSON-совместимые входы и проверяемые выходы: числа, строки, булевы значения, `None`, списки и словари. Множества допустимы внутри решения; итогом может быть их размер. Прямой проверяемый результат типа `set` потребует отдельного расширения контракта, а не молчаливого приведения к списку.

Предпочтения имеют источники, категории и историю версий. Новый явный отзыв может пометить прежнее правило той же категории заменённым; старое правило и его основание сохраняются. Если исправленный или отозванный отзыв был единственным основанием правила, оно автоматически перестаёт применяться ещё до обращения к модели. Другое действующее основание сохраняет правило. Пропущенный отзыв ничего не доказывает. Существующий учебный материал не перезаписывается из-за позднего отзыва: обновлённые предпочтения влияют на следующие материалы, прежние ID, решения и выплаты сохраняются.

Универсальные идеи попадают в `sharedProposals` со статусом `needs-independent-review`. Сервис знает только свой профиль и не придумывает подтверждение от другого ученика. Он не меняет общие инструкции, исходники, AGENTS.md, удалённый репозиторий или чужие профили. Проверка и принятие общего предложения — отдельная операция.

## Повторы, сбои и остановка

Один профиль готовит один пакет одновременно. Повтор той же отправки возвращает существующий результат; повторное чтение статуса не вызывает Codex. На один снимок работы предусмотрено не более двух явных попыток. После аварийной остановки незавершённая работа становится `interrupted` и требует явного повторения. При закрытии старый обработчик больше не пишет в профиль.

Пределы ожидания по умолчанию: 90 секунд на выделение предпочтений, 420 на подготовку материала и 300 на независимый разбор. Python-проверки имеют собственный короткий предел. Это фоновые операции; страница показывает стадию и остаётся доступной. Предел можно задать для процесса, без изменения глобальных настроек Codex.

Изменённый отзыв может обновить предпочтения, но не создаёт ещё один экземпляр уже опубликованной ветки. Публикация использует стабильные ID по исходному уроку и типу ветки. Изменение смысла уже начатых заданий автоматически не производится. Полезные данные не считаются завершённым обучением: прежняя жёлтая тема не закрывается от подготовки нового материала.

Отправка отдельной практики обновляет предпочтения и возвращает существующие ссылки исходного маршрута. Новые «разборы разбора» не порождаются даже при повторной ошибке. Для старой работы над ошибками без отдельного продолжения в roadmap отзыв учитывается успешно, без выдуманной следующей темы и без повторной генерации старого курса.

Схема и независимый рецензент не доказывают педагогическое качество математически. Неясный текст, недостаточные граничные случаи и общие ошибки модели остаются возможны. Поэтому публикация отклоняется при замечаниях, ученик сохраняет возможность дать уточняющий отзыв, а общие изменения проходят отдельную проверку.
